# 复用现有布局的独立 H5

共创草案 · 未生效。承接用户最新反馈；本轮布局改造未修改线上服务；既有 Shift 标签优化已作为基线迁入 fork。

## 已确认方向
- 原话：“我希望完全搬运当前网页版的布局”。
- 现有 herdr-remote 的 HTML/CSS/JS 已经是 H5/PWA，适配 H5 不需要重新搭建界面。
- 以当前线上版本的布局、导航、工作区/Agent 展示、终端/历史/输入/确认操作为基准；不采用上一份原型的中文首页、底部工作台导航或对话重排。
- H5 独立运行，普通浏览器和飞书内 WebView 都可加载。飞书只是可选访问入口，不是页面、Relay、数据或控制链路的必需运行平台。

## 改造边界
- 复用当前 web/ 与 Relay；兼容修复不得改变现有信息架构和常用路径。
- 只针对真实发现的飞书 WebView 输入法、返回、前后台重连、屏幕安全区域兼容问题做最小改动。
- 飞书 SDK 只在需要端内能力的适配层使用；未处于飞书或 SDK 不可用时不阻止普通浏览器运行。
- 保留独立访问认证方式；普通浏览器路径不能只依赖飞书身份服务。飞书免登是可选能力，不能把免登能力失败设计成所有 H5 用户不可访问。每条认证路径仍必须有完整授权边界。
- 是否第一版增加飞书免登，以及采用哪个应用、独立访问认证方式如何与免登共存，尚未定稿；不能承接前一版“只有飞书登录网关”的单一认证假设。
- 不增加机器人、企业共享工作台、新的对话布局、任务调度或文件同步。

## 拟定验收
- 相同快照、相同 viewport、相同主题下，与当前网页版截图对比验证布局与操作路径一致；动态时间等字段单独归一化。
- 不加载飞书 SDK 的普通手机/桌面浏览器能按独立认证方式查看和操作获准 Agent。
- 真实手机飞书 WebView 验证工作区、终端、输入、确认、返回与前后台重连；普通 Chrome 不能替代。
- 飞书适配层失败不破坏独立浏览器；认证失败不开放未授权访问。
- 所有写入只指向所选的稳定 Agent/当前请求，重连不自动重发。
- 用户判断现有布局被完整保留、手机操作仍方便。

## 当前状态
上一份重排原型被用户否决；本候选尚未交叉审核或正式确认。没有施工、上线或飞书配置完成声明。下一步围绕当前真实网页确定端内兼容与可选登录范围，不再以被否决的原型作为规格。
